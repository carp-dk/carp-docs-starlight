A study is a few JSON files. The app reads them on your phone in [Step 2](/start/run-your-study/), and you upload the same files to the CARP Portal when you go live.

## How a study runs

Every study follows the same flow on the participant's phone. The files on this page decide what happens at each step.

<Steps>

1. **Join.** The participant joins with an email invitation (username and password) or, if the study allows it, anonymously with a QR code or a 5-character code. The app shows the invitation with the study's purpose, from [`protocol.json`](#protocol).

2. **Give consent.** The participant reads the informed consent and signs that you may collect their data, from [`consent.json`](#consent).

3. **Allow permissions.** The app asks for the permissions the protocol's measures need, such as location or activity.

4. **Collect.** The app runs the protocol: each task starts when its trigger fires, its measures collect data, and the data goes to the protocol's data endpoint.

5. **Leave.** The participant can leave the study at any time from their profile.

</Steps>

All texts along the way are shown in the phone's language, from the [translation](#translations) files. See the screens in [What participants see](/start/run-your-study/what-participants-see/).

## The files

| File | What it holds | Needed? | Section |
| --- | --- | --- | --- |
| [`protocol.json`](#protocol) | What to collect, from which device, and when | Yes | [Protocol](#protocol) |
| [`consent.json`](#consent) | The informed consent the participant reads and signs | No | [Consent](#consent) |
| [`en.json`, `da.json`, …](#translations) | The texts, one file per language | If you use keys | [Translations](#translations) |

<Aside type="caution" title="Generate the JSON, don't write it">
The JSON files are **generated** from Dart code, with [CARP Mobile Sensing](/carp-mobile-sensing/) for the protocol and [Research Package](https://pub.dev/packages/research_package) for the consent. Editing the JSON by hand is easy to get wrong: a missing `__type` or a misspelled measure only fails when the app runs. Change the Dart and generate the file again.
</Aside>

To generate a file, run the Dart code in a test or a small script and save the result with `toJsonString(...)`. Try it with the buttons below.

## Protocol

The protocol answers four questions:

| Question | In the protocol | In this example |
| --- | --- | --- |
| **Where** is data collected? | Device | The phone |
| **What** is collected? | Measures | Steps and battery |
| **When** is it collected? | Trigger | Right away, all the time |
| **Where** does data go? | Data endpoint | A database on the phone |

<Generate dart={protocolDart} json={protocolJson} file="protocol.json" />

CAMS adds the `Monitoring Smartphone` task itself. It records errors and task events.

To collect more, add a measure from [Available packages](/carp-mobile-sensing/sampling-packages/available-packages/). To collect at other times, change the [trigger](/carp-mobile-sensing/domain/triggers/). To ask the participant something, add a [task](/carp-mobile-sensing/domain/tasks/). Everything a protocol can hold is in [Study protocol](/carp-mobile-sensing/domain/study-protocol/).

## Consent

The informed consent is what a participant reads before the study starts. It is how you inform them: what the study is about, what data it collects, how their privacy is protected, what they will be asked to do, and that they can leave at any time. It can hold anything the participant should know before agreeing.

It is a short flow: the participant reads the sections, reviews them, signs with name and finger, and is done. Each section has a type (Overview, Data gathering, Privacy, Study tasks and more) that sets its icon and default title. See how it looks in the app in [What participants see](/start/run-your-study/what-participants-see/#5-onboarding-part-2-of-3-consent).

<Generate dart={consentDart} json={consentJson} file="consent.json" />

No `consent.json` means there is nothing to sign, and the participant goes straight into the study.

## Translations

The protocol and consent don't contain the texts. They contain **keys**, such as `study.purpose`. Each language has a file that maps the keys to the text, and the app shows the file that matches the phone's language. `en.json` is used when there is no file for that language.

The three files have the same keys. Only the texts differ. Add as many languages as you need, one file each. Write `en.json` first, then let an AI tool translate it into the other languages, and have a native speaker check the result. Keep the keys unchanged, only the texts are translated.

<Aside type="tip" title="The files stay the same">
The same files run on your phone, on a test server and in production. Only the server and sign-in change.
</Aside>
