`lib/domain/` describes **what a study is**. Nothing in it collects data: it holds the classes you use to write a study protocol, and the data classes a study produces.

It extends the platform-independent [`carp_core`](https://pub.dev/packages/carp_core) domain model with what a phone needs (`Smartphone`, `SmartphoneStudyProtocol`, `AppTask`, data endpoints, transformers). Both are serialized to JSON, so a protocol can be stored, sent to a server, and deployed to a phone.

![The CARP study protocol domain model](/carp-mobile-sensing/images/carp_protocol_domain.svg)

A protocol reads left to right: a **trigger** says *when*, a **task** says *what to do*, and its **measures** say *which data*. Task controls join triggers to tasks.
